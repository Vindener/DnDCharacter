# DnD Product Guidelines

## Core DnD Loop
The DM describes the situation.
Players describe actions.
The DM resolves consequences.

The UI should help users act quickly during that loop.

## Dice
- d20 is used for ability checks, saving throws, and attack rolls.
- Roll result = d20 + ability modifier + proficiency if applicable.
- Advantage = roll two d20 and use the higher.
- Disadvantage = roll two d20 and use the lower.
- Damage rolls are separate from attack rolls.
- Critical success/failure should be based on natural d20 results, not the total.

## Character Sheet
Prioritize:
- HP;
- Temp HP;
- AC;
- Initiative;
- Speed;
- Proficiency;
- Ability modifiers;
- Saving throws;
- Skills;
- Attacks;
- Spell slots;
- Conditions;
- Quick notes.

Play Mode should support fast in-session actions.
Edit Mode should contain full configuration and longer forms.

## Create Character
Recommended flow:
1. Identity
2. Race
3. Class
4. Background
5. Ability scores
6. Combat basics
7. Equipment
8. Magic
9. Personality
10. Storage/share
11. Review

Background should affect mechanics where the app supports it, not remain only descriptive text.

## Spellbook
Spell cards should preserve:
- level;
- school;
- casting time;
- range;
- components;
- duration;
- concentration;
- ritual;
- class/source;
- prepared/known/favorite state.

Spellbook should support quick lookup during play and integration with Character Sheet magic workflows.

## Bestiary
Monster cards should prioritize:
- name;
- type;
- CR;
- AC;
- HP;
- speed;
- main traits;
- actions;
- reactions;
- add to encounter.

Bestiary should support DM quick view and encounter preparation, not only long-form reading.
