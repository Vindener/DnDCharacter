# Skill: create-android-component

## Goal

Створювати компоненти, які:

- добре працюють на Android;
- не ламають поточний стиль коду;
- мають коректні TypeScript типи;
- легко інтегруються у `src/screens`, `src/shared/components` або `src/modules`.

## Rules

1. Використовуй функціональні компоненти.
2. Використовуй `TypeScript` без `any`.
3. Для інтерактивних елементів віддавай перевагу `Pressable`.
4. Для Android додавай `android_ripple`, якщо це доречно.
5. Якщо потрібна візуальна глибина, використовуй `elevation`.
6. Стилі винось у `StyleSheet.create`.
7. Якщо в фічі вже є окремий `style.ts` або `styles.ts`, дотримуйся локальної конвенції.
8. Якщо компонент використовує кольори теми, бери їх зі store/теми, а не хардкодь без потреби.
9. Не клади Firestore/Auth логіку прямо у візуальний компонент, якщо її можна винести в service або hook.
10. Якщо компонент працює з навігацією, типізуй route/navigation params.

## Expected output

Коли генеруєш компонент:

- дай повний робочий код;
- включи потрібні імпорти;
- не залишай плейсхолдерів типу `TODO` або `...`;
- називай пропси і колбеки явно;
- якщо потрібно, коротко вкажи, куди саме в структурі репозиторію його краще покласти.

## Repo-specific guidance

- Маленькі універсальні UI-блоки: `src/shared/components/`
- Великі повторно використовувані модулі: `src/modules/`
- Екран-рівень: `src/screens/<Feature>/`
- Якщо компонент працює з персонажем, спочатку перевір типи в `src/types/Character.ts`
- Якщо компонент змінює локальні дані персонажа, перевір `src/context/Character-store.ts`
